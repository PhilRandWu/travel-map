# 已知问题

> 更新于 2026-10-21，剩余 MVP（时间轴 / 统计 / 全局联动）实现时记录。

## 待复验：高铁轨迹 hover 的自动化命中不稳定

- **现状**：航班弧线可稳定命中 hover，tooltip、互斥淡出与点击选中均已通过无头浏览器验证。
- **未闭环**：同一套按颜色扫描的浏览器脚本在阶段 3 早期实现中曾命中 `G7558`，但拆分展示 hook 后未再稳定命中高铁折线。单测已验证高铁点串经过全部 waypoint，尚不能据此认定浏览器端 hover 有回归。
- **可能原因**：示例数据中的杭州—上海线段在初始镜头下很短，且会经过城市发光点、名称浮标和自动旋转区域；也可能是 hook 拆分引入了交互回归。
- **后续处理**：
  1. 固定相机 POV 并临时隐藏城市名称，在杭州—上海局部做人工 hover；
  2. 若确认回归，检查 `pathsData`、`onPathHover` 与 `pathLabel` 的绑定；
  3. 增加可重复的浏览器级测试，避免依赖全画布颜色扫描。

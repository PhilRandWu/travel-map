# v0.3 Journey Memory Experience Master Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 将现有平铺式旅行地图升级为“旅行档案 → 旅程 → 地点篇章 → 照片回忆”的旅程阶段式个人回忆体验，并以可控、可降级的电影化动效完成收束。

**Architecture:** 先建立 `Journey` 数据边界、`JourneyScope` 导航边界和常居城市语义；再在同一数据边界上实现四级照片资产、地点篇章、回忆舞台与回忆星图；最后把路线生长、光门转场、章节卡、载具拖尾、环境漂移和低帧率降级接入已经稳定的结构。三个子计划分别产出可独立运行和验收的软件，不把视觉特效建立在错误的数据范围上。

**Tech Stack:** Vite、React 19、TypeScript、Tailwind CSS 4、Vitest、Testing Library、jsdom、`react-globe.gl`、Three.js、Sharp、Playwright 浏览器验收。

---

## 1. 交付目标

v0.3 完成后，用户打开应用会先看到按年份组织的旅行档案，而不是全部交通段和到访节点的平铺时间轴。选择一段旅程后，地图、路线、地点、统计、章节轴与回放都只读取该旅程的数据；常居城市以独立双环标记点亮，不计入旅行目的地。进入地点篇章后，用户可以从精选照片或全部照片进入沉浸式回忆舞台，并在桌面端体验完整电影化转场、在 390px 宽度下完成核心浏览。

本计划覆盖设计规格 v1.2 的全部 23 个章节。用户举例的日期不写入组件、测试或文案；示例旅程只使用仓库中已有的真实示例数据日期。

## 2. 当前基线

- 数据仍是 `Trip[]` / `Visit[]` 平铺结构，`meta.version = 1`。
- 现有 5 段交通、5 次到访中有 2 次北京日常生活停留，必须从旅程地点数据中移除。
- 现有 `Selection` 已能表达 `none / visit / trip / city`，但没有旅程范围。
- 现有 `Timeline` 已具备回放、倍速、拖动和轨迹联动，可在旅程过滤后的节点上复用。
- 现有缩略图管线只生成 480px WebP，不能支撑小卡、拼图、舞台预览和原图四级加载。
- 现有动画集中在星点闪烁、相机飞行、主图 Ken Burns 与载具移动，没有统一的动效强度、场景编排和低帧率降级。
- 当前测试全部是 Vitest 纯函数测试，组件交互、焦点管理和可访问性缺少测试基础设施。

```text

  ├── 数据契约与迁移
  ├── 校验与派生

  └── 常居城市语义
        ↓ 数据闸门通过
B 照片回忆
  ├── 四级图片资产
  ├── 地点篇章与旅程封面
  ├── 回忆舞台、自动播放与缩放
  ├── 回忆星图与移动端降级
  └── 焦点、键盘与 390px 验收
        ↓ 照片闸门通过
C 动画收束
  ├── 动效令牌与三档设置
  ├── 页面唤醒与环境层
  ├── 旅程展开与路线生长
  ├── 光门、章节卡与照片转场
  ├── 旅程回放、拖尾与到达波纹
  └── 低帧率降级与最终回归
```

阶段 A 不得依赖阶段 B 或 C 的新文件；阶段 B 只能消费阶段 A 已锁定的类型与范围函数；阶段 C 只增强稳定组件，不重新定义数据范围或照片索引规则。

## 6. 跨阶段契约

以下名称在三个子计划中必须完全一致，执行时不得自行改名。

```ts
export type JourneyTheme = 'amber' | 'cyan' | 'sage' | 'rose'

export interface Journey {
  id: string
  title: string
  startDate: string
  endDate: string
  epigraph?: string
  summary?: string
  theme: JourneyTheme
  coverPhotos: Array<{ visitId: string; file: string }>
}

export interface JourneyScopeArchive {
  kind: 'archive'
}

export interface JourneyScopeJourney {
  kind: 'journey'
  journeyId: string
}

export type JourneyScope = JourneyScopeArchive | JourneyScopeJourney

export type MotionLevel = 'calm' | 'cinematic' | 'immersive'

export type MemoryMode = 'featured' | 'all'
export type MemoryView = 'stage' | 'constellation'

export type MemorySource =
  | { kind: 'visit'; visitId: string }
  | { kind: 'journey'; journeyId: string }

export type PhotoVariant = 'blur' | 'sm' | 'md' | 'preview'
```

`JourneyScope` 只决定数据范围；`Selection` 只决定当前聚焦对象；`MemoryOverlay` 只决定照片浮层。回放状态不进入数据层，任何范围切换都必须停止旧回放。

## 8. 数据验收

阶段 A 结束时必须同时满足：

- `meta.version` 为 `2`，顶层包含 `journeys`。
- 每条 `Trip` 与 `Visit` 都有有效的 `journeyId`。
- `Visit.city === meta.homeCity` 会产生 error，示例数据中不存在这种记录。
- 旅程 `startDate <= endDate`，交通与到访完全落在旅程区间内。
- 封面 0–5 张；坏 `visitId`、坏 `file` 均产生 error。
- 示例数据至少包含两段日期不重叠的旅程，且两段旅程的筛选结果无交叉。
- “显示其他旅程”默认关闭；开启后只渲染 6%–10% 的星尘轨迹，不显示其他城市名、不可交互、不改变统计。
- 用户举例的日期不出现在 JSON、组件或测试快照中。

## 9. 照片验收

阶段 B 结束时必须同时满足：

- 每张照片生成 `blur / sm / md / preview` 四种派生资产，原图继续留在 `public/photos/`。
- 时间轴、章节轴、拼图和胶片条不请求 preview 或 original。
- 舞台只挂载当前、上一张缓存和下一张预加载，只有缩放时请求 original。
- 有精选时默认精选；无精选时隐藏精选入口并直接显示全部。
- 同一地点不同日期的到访按独立章节处理。
- 舞台关闭后焦点返回打开按钮；Esc 只关闭最上层浮层。
- 390px 宽度无横向页面溢出，胶片条和左右切换可操作。

## 10. 动效验收

阶段 C 结束时必须同时满足：

- 右上角可切换静谧、电影感、沉浸，刷新后仍保留；系统 `prefers-reduced-motion: reduce` 强制静谧。
- 首次进入、旅程展开、照片舞台、章节切换各只有一个主运动。
- 路线流光同一时刻最多一条，城市到达波纹只播放一次。
- 只有选中轨迹缓慢呼吸；高铁移动时最多 6 个短促摩擦光点，摩擦光不脱离路线。
- 旅程卡三层封面视差不超过 3px、容器倾斜不超过 2°；触屏不倾斜；护照与照片回忆舞台微尘最多 20 个。
- 回忆舞台有静态胶片颗粒；返回上级时当前层先退后 280–420ms，背景地图再恢复清晰。
- 页面进入后台时暂停自动回忆、星点漂移、路线流光与微尘。
- 连续 2 秒低于目标帧率时自动降低一档，但保留用户原设置。
- 快速切换旅程时旧动画在 120ms 内中止，新镜头从当前位置继续。

## 14. 风险控制

| 风险 | 控制措施 |
|---|---|
| 先做动画后迁移数据导致返工 | Gate A 未通过不得开始 B；Gate B 未通过不得开始 C |
| 两段旅程共享照片或城市状态 | 所有渲染只接受 `scopeTravelData` 的结果；测试明确断言跨旅程隔离 |
| 组件继续膨胀到 300 行以上 | A7 起按档案、护照、章节、地点、舞台拆分文件 |
| 四级资产管线破坏现有照片 | 保留原文件不动；先写资产测试，再切换 UI URL |
| 回忆舞台一次挂载大量图片 | 只渲染当前、下一张和胶片条 sm；星图按视口挂载 |
| 动效造成眩晕或卡顿 | 单主运动、三档偏好、减少动态优先、连续低帧率降级 |
| 键盘与触屏只实现其一 | 每个交互任务同时写键盘测试与触控验收项 |
| 示例日期被误认为产品规则 | 数据契约不包含固定日期常量；测试只读取 JSON 实际值 |

## 15. 执行顺序

1. 依次执行 A1–A10，通过 Gate A。
2. 依次执行 B1–B10，通过 Gate B。
3. 依次执行 C1–C10，通过 Gate C。
4. 更新 `docs/PLAN.md` 的任务状态与执行记录。
5. 仅在用户明确要求后提交 Git；本轮文档规划不执行 commit。

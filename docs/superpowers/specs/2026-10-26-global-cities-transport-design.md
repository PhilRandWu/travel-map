> 体验主张：城市选择不再受内置小城市表限制，旅行方式也不再只有飞机和高铁。用户可以用离线全球城市库记录真实的出发、经停与到达，并为飞机、高铁、地铁、轮船和汽车获得各自完整的路线、载具、运动阶段与导演镜头。

---

## 1. 设计摘要

本设计包含两条相互关联但可独立验收的能力：

1. 建立约 560–590 个城市的离线目录，中国为主，国际部分覆盖各国首都、主要城市和热门旅行城市；支持中文、英文、拼音、常用别名及国家/地区搜索。
2. 将交通类型从飞机/高铁扩展为飞机、高铁、地铁、轮船和汽车。五种方式共用 `from → waypoints → to` 行程模型，均支持经停，并由统一交通注册表驱动轨迹、载具、阶段、镜头、统计、时间轴和搜索。

城市目录只在懒加载编辑器中消费。用户选中的城市仍写入现有 `data.cities`，因此地图、时间轴、校验和统计不需要在线请求，也不需要改变城市点亮机制。

## 2. 已确认决策

| 主题 | 决策 |
|---|---|
| 城市数量 | 约 560–590 个；中国约 340 个，国际约 220–240 个 |
| 城市数据 | 离线内置；生成后的静态数据提交仓库，运行时与常规构建不联网 |
| 中国数据 | DataV 行政区中心的离线快照，人工补齐港澳台及多音字校正 |
| 国际数据 | Natural Earth 地名与坐标，结合 `world-countries` 国家翻译和人工别名补充 |
| 搜索 | 中文、英文、拼音、常用别名、国家、省份；无在线地理编码 |
| 交通类型 | `flight / train / metro / ship / car` |
| 经停 | 五种方式都支持，最多 4 个有序经停城市，且为实际停靠点 |
| 技术路线 | 统一交通注册表 + 通用路线模型；不再为每种方式复制完整消费链 |
| 载具表现 | 五种独立斜透视 SVG 载具，各自拥有光晕、轨迹、拖尾和运动特征 |
| 统计结构 | 从飞机/高铁二元计数改为交通段总数和按类型统计 |
| 本次不做 | 在线地理编码、真实道路/轨道/航道、发布、昼夜皮肤、后端、移动端专项 |

## 3. 目标与非目标

### 3.1 目标

1. 编辑到访或交通时，可以搜索并自动使用全球主要城市的离线坐标。
2. 五种交通方式都能记录两座城市之间的行程，并支持最多 4 个经停城市。
3. 每种交通方式具有独立且可辨识的路线线型、颜色、载具模型、运动阶段、速度和导演镜头。
4. 所有交通方式复用同一播放、暂停、倍速、跳转、到达和退出状态机。
5. 时间轴、城市卡片、地点篇章、封面说明、编辑器列表和全局搜索对五种方式一致展示。
6. 统计面板不再依赖二元字段，能够稳定展示五种交通构成。
7. 城市目录不增加首屏加载负担，损坏目录或旧交通数据不会使页面崩溃。

### 3.2 非目标

- 不接入在线地理编码、地图搜索、路线规划或第三方地点服务。
- 不绘制真实道路、铁路、地铁线路、航道或航空导航路径。
- 不模拟真实交通物理、时刻表、拥堵、天气或班次延误。
- 不把 SVG 载具升级为外部 3D 网格模型。
- 不改变照片、旅程、到访、城市点亮或发布流程。
- 不增加移动端专项交互设计。
- 不在本阶段实现昼夜皮肤。

## 4. 全球离线城市目录

### 4.1 规模与覆盖

提交后的目录必须满足：

- 总量 400–600，目标 560–590。
- 中国城市不少于 300 条，并占目录多数。
- 国际条目 220–240 条，其中覆盖所有纳入目录的国家/地区至少一个首都或首府。
- 国际非首都条目优先选择主要城市和热门旅行城市，例如纽约、洛杉矶、旧金山、巴塞罗那、米兰、慕尼黑、悉尼、墨尔本和迪拜。
- 同一国家内的同名城市必须有稳定区分，不允许只靠显示名去重。

中国部分以地级及以上城市、直辖市、港澳和台湾主要城市为主，不追求收录所有县级行政区。

### 4.2 数据来源

| 数据 | 来源 | 说明 |
|---|---|---|
| 中国城市 | DataV 行政区 `_full` 数据 | 提取地级行政区中心、名称和所属省级行政区 |
| 港澳台补充 | 人工核对静态补充表 | 补齐 DataV 未提供完整城市层级的地点 |
| 国际城市 | Natural Earth populated places | 提供坐标、英文名、行政归属和国家代码基础 |
| 国家翻译 | `world-countries` | 生成中文国家名与 ISO 代码 |
| 中文别名 | 人工补充表 | 覆盖中文名、当地常用名、简称和旅行常用称呼 |
| 拼音 | 构建期拼音工具 + 人工覆盖 | 生成中国城市拼音 ID 与搜索别名，修正多音字 |

数据生成后必须记录来源和许可说明。新增 `docs/DATA_SOURCES.md`，README 只保留简短入口。

### 4.3 生成流程

新增手动命令 `pnpm cities:build`，仅用于更新城市目录：

1. 获取或读取外部源数据。
2. 规范化名称、国家、行政区和坐标。
3. 合并人工补充、别名与拼音。
4. 去重并生成稳定 ID。
5. 执行总量、占比、字段、唯一性和坐标校验。
6. 校验通过后，按区域写入 `src/data/cities/*.json`。

常规 `pnpm build`、开发服务器和浏览器运行不得调用该网络流程。生成失败时不得覆盖已有目录。

### 4.4 目录类型

保持领域模型 `City` 不变。新增仅供编辑器搜索使用的目录条目：

```ts
type CityCatalogKind =
  | 'china-city'
  | 'capital'
  | 'major-city'
  | 'travel-city'

interface CityCatalogEntry {
  city: City
  nameEn: string
  aliases: string[]
  countryCode: string
  kind: CityCatalogKind
  priority: number
}
```

`city` 使用现有 `City` 字段；`province` 对中国表示省级行政区，对国际城市表示可用的州/地区名，缺失时回退国家名。

### 4.5 ID 规则

- 现有 10 个内置城市 ID 保持不变。
- 中国新增城市使用无冲突拼音 ID，例如 `nanjing`、`wuhan`。
- 国际城市使用城市英文 slug 与国家 ISO2 组合，例如 `tokyo-jp`、`new-york-us`。
- 发生 slug 冲突时追加稳定序号，生成器负责保证全局唯一。
- 已被旅行数据引用的 ID 不得因重新生成而改变。

### 4.6 搜索与排序

搜索在编辑器内完成，不依赖网络。标准化规则包括：

- 去除首尾空白并忽略大小写。
- 拉丁字母进行重音分解并去除组合附加符。
- 中文城市名生成带/不带“市”等常见行政后缀的别名。
- 搜索字段包含中文名、英文名、ID、拼音、别名、省份、国家、国家代码。

排序顺序：

1. 标准名、ID 或别名精确匹配。
2. 标准名或主要别名前缀匹配。
3. 任意字段前缀或包含匹配。
4. 相同匹配级别下，用户已有城市优先，其次根据目录 `priority` 排序。

空查询优先返回 `data.cities` 中已有城市，再补足热门城市，默认最多 8 条。下拉项显示中文名、英文名或别名提示、经纬度、省份/国家和 ID；选中后坐标立即回填。

找不到城市时继续支持现有“自定义城市 + 手工经纬度”回退。

### 4.7 加载与持久化边界

- `src/lib/cities.ts` 保留现有核心内置表和同步解析能力，服务主地图与旧数据。
- 全球城市目录及搜索元数据只由懒加载编辑器引用，不进入首屏主包。
- 编辑器选中目录城市后，通过现有保存流程写入 `data.cities`。
- 主地图、时间轴、校验和统计继续只依赖 `data.cities` 与核心内置表。
- 手工编辑 JSON 引用非核心目录城市时，必须同时把该城市写入 `data.cities`；校验错误需要说明这一点。

## 5. 交通领域模型

### 5.1 类型扩展

```ts
type TransportType = 'flight' | 'train' | 'metro' | 'ship' | 'car'
```

`Trip` 字段结构不变：

```ts
interface Trip {
  id: string
  journeyId: string
  date: string
  type: TransportType
  from: string
  to: string
  waypoints: string[]
  note?: string
}
```

`waypoints` 更新为五种方式通用的有序经停城市 ID。`TravelMeta.version` 不升级，现有 `flight/train` 数据直接兼容。

### 5.2 经停语义

- 路线顺序固定为 `from → waypoints[0] → … → to`。
- 最多 4 个经停城市。
- 出发城市、到达城市和已有经停城市不能被重复加入。
- `from === to` 是无效行程。
- 每个经停城市是实际停靠点；载具完成当前段后停留，再开始下一段。
- 经停城市不因出现在路线中而自动成为“到访城市”，也不点亮城市或进入到访统计。
- 选中或回放该行程时，经停城市显示模式色节点、名称和一次到达波纹。

### 5.3 校验

`validateTravelData` 接受五种类型，并检查：

- 类型属于 `TransportType`。
- `waypoints` 始终为数组。
- `from`、`to` 和每个经停城市引用存在。
- `from !== to`。
- 路线节点不重复。
- 经停数量不超过 4。

旧的“flight 不应配置 waypoints”警告删除。未知类型、缺失城市、重复路线节点和超量经停必须作为错误报告，不由界面静默修复。

## 6. 编辑器交互

### 6.1 交通选择器

交通选择器抽成独立组件，使用图标和中文名称展示五项：

| 类型 | 名称 | 备注提示 |
|---|---|---|
| `flight` | 飞机 | 航班号 |
| `train` | 高铁 | 车次 |
| `metro` | 地铁 | 线路 / 区间 |
| `ship` | 轮船 | 船班 / 航线 |
| `car` | 汽车 | 自驾路线 |

桌面端优先横排五项；空间不足时自动折成两行。每项保留可访问名称、选中态和至少 44px 的操作高度。

切换交通方式不得清空经停城市，只更新轨迹、载具、阶段、镜头和提示文案。

### 6.2 经停编辑器

经停编辑器抽成独立组件，对五种方式始终显示：

- 添加最多 4 个经停。
- 每个下拉框排除出发、到达及其他已选经停城市。
- 支持删除和上移/下移调整顺序。
- 空状态说明当前方式的经停会形成分段路线。
- 保存时再做一次去重和顺序过滤，避免绕过 UI 的重复数据。

### 6.3 保存行为

- `saveTrip` 对五种方式执行相同去重与持久化逻辑。
- 所有被选中城市继续通过 `withCity` 写入 `data.cities`。
- 旅程日期扩展逻辑不变。
- 新行程默认类型仍为飞机。
- 编辑已有行程时保留原类型和经停顺序。

## 7. 统一交通注册表

新增 `src/lib/transportModes.ts`，作为以下能力的唯一配置来源：

- 中文名称、短名称、图标和可访问标签。
- 备注提示与占位符。
- 轨迹类型、颜色、虚实、线宽、高度和重复走廊偏移。
- 载具 SVG、光晕、阴影和拖尾样式。
- 运动阶段、阶段权重、时长范围和姿态系数。
- 导演镜头高度、前导角和 HUD 名称。
- 准备、经停和到达文案。

`TRANSPORT_TYPES` 使用只读有序元组。所有展示代码通过 `TRANSPORT_MODES[type]` 或辅助函数读取配置。除运行时防御逻辑外，组件中不得再出现：

```ts
type === 'flight' ? ... : ...
```

或把全部非飞机类型默认当成高铁的分支。

## 8. 路线模型与视觉

### 8.1 通用路线结构

轨迹层输出一份通用 `TransportRoute`，至少包含：

```ts
interface TransportRoute {
  trip: Trip
  type: TransportType
  stops: City[]
  legs: Array<{ from: City; to: City }>
  points: [number, number][]
  altitude: number
  label: string
  midLat: number
  midLng: number
}
```

- 通用结构负责距离、城市序列、焦点、标签、选择键和回放。
- 飞机在展示适配层中按每个 leg 拆成弧线，但选择和统计仍以一条 `trip` 为单位。
- 高铁、地铁、轮船和汽车使用拼接后的贴地或贴海路径。
- 缺失任何路线城市时跳过整条不完整轨迹，并保留校验错误。

### 8.2 视觉参数

| 方式 | 主色 | 路线 | 高度与运动特征 |
|---|---|---|---|
| 飞机 | 冰青 `#A5F3FC` | 高空虚线大圆弧，重复走廊分层抬高 | 高度随距离变化，逐段起飞、巡航、下降 |
| 高铁 | 琥珀 `#FBBF24` | 贴地实线，重复走廊左右偏移 | 稳定地面高度，平滑加速和制动 |
| 地铁 | 珊瑚 `#FDA4AF` | 短划线，沿线显示密集站点光环 | 更低高度，转向响应更快，轻微侧倾 |
| 轮船 | 海蓝 `#60A5FA` | 细虚线，带轻微高度波动 | 海面附近巡航，轻微横摇和上下浮动 |
| 汽车 | 鼠尾草绿 `#86EFAC` | 细实线，重复走廊左右偏移 | 低空行驶，转向灵敏，轻微车身侧倾 |

相同城市对的重复路线统一去重：飞机按高度分层，其余方式按左右车道偏移。往返方向共享同一走廊。

### 8.3 经停与路线标记

- 路线 tooltip 与摘要始终显示完整 `A → B → C → D`。
- 选中或回放时，在经停城市显示小型模式色圆环和名称。
- 载具进入经停城市后触发一次波纹。
- 经停标记不修改城市点亮、到访数量或旅行统计。

## 9. 载具、运动与导演镜头

### 9.1 独立载具资源

保留：

- `public/vehicle-icons/flight-3d.svg`
- `public/vehicle-icons/train-3d.svg`

新增：

- `public/vehicle-icons/metro-3d.svg`
- `public/vehicle-icons/ship-3d.svg`
- `public/vehicle-icons/car-3d.svg`

五张资源使用一致斜透视、高光和阴影语言，但造型互不复用。载具资源只在载具回放层加载，不进入首屏。

### 9.2 运动阶段

| 方式 | 阶段 |
|---|---|
| 飞机 | 滑跑 → 起飞 → 巡航 → 下降 → 接地 |
| 高铁 | 发车 → 加速 → 区间巡航 → 制动 → 进站 |
| 地铁 | 离站 → 加速 → 区间运行 → 制动 → 到站 |
| 轮船 | 离港 → 加速 → 海上巡航 → 减速 → 靠港 |
| 汽车 | 启动 → 加速 → 公路行驶 → 减速 → 抵达 |

每个 leg 使用当前方式的完整阶段序列。每到一个中途经停点：

1. 当前 leg 完成到站阶段。
2. 显示 700ms 停靠状态。
3. 经停文案分别为“经停 / 停站 / 到站 / 靠港 / 途经 + 城市名”。
4. 继续下一 leg。

整条行程的运动时间预算按总距离计算，并受方式上限约束；经停停留时间另行叠加。相位时间按权重分配，避免 4 个经停把回放拉长到不可接受。

### 9.3 时长与姿态

建议初始参数：

| 方式 | 运动时长范围 | 俯仰 | 侧倾/浮动 |
|---|---:|---|---|
| 飞机 | 5.5–8.5s | 起飞抬头、下降低头 | 转弯最大约 12°，轨迹高度包络 |
| 高铁 | 6–9s | 0 | 基本水平，仅极轻微转向侧倾 |
| 地铁 | 4.8–7s | 0 | 比高铁更快的轻微侧倾 |
| 轮船 | 7.5–10.5s | 0 | 小幅横摇与上下浮动 |
| 汽车 | 5.5–8s | 0 | 转向时轻微侧倾 |

具体视觉参数按注册表配置，测试断言应有上下界而不是锁定单一毫秒值。

### 9.4 导演镜头

| 方式 | 镜头高度 | 北向前导 | 跟拍特点 | 准备文案 |
|---|---:|---:|---|---|
| 飞机 | 0.62 | 2.4° | 远景跟拍，保留航线和目的地 | 准备起飞 |
| 高铁 | 0.34 | 2.4° | 中距离沿线跟拍 | 准备发车 |
| 地铁 | 0.25 | 1.8° | 距离最短、更靠近路线 | 准备离站 |
| 轮船 | 0.43 | 2.0° | 略高、更宽的海面远景 | 准备离港 |
| 汽车 | 0.30 | 2.1° | 低空近距离跟拍 | 准备出发 |

现有准备、移动、抵达停留、镜头拉回和异常恢复状态机保持统一。暂停、倍速、跳转、切换旅程和卸载必须同时冻结或恢复载具、镜头、拖尾和 HUD。

### 9.5 拖尾与地面效果

| 方式 | 效果 |
|---|---|
| 飞机 | 高空尾迹 |
| 高铁 | 轨道地面光带 |
| 地铁 | 站台脉冲和短轨光 |
| 轮船 | V 形船尾航迹 |
| 汽车 | 短促道路光痕 |

拖尾颜色、宽度、透明度和地面效果由交通注册表驱动，不能继续使用“是否飞机”的二元分支。

## 12. 错误处理与性能

### 12.1 错误处理

- 城市生成任何校验失败时退出且不覆盖旧目录。
- 生成器先写临时目录，完整校验后再替换目标目录。
- 目录运行时加载失败时，编辑器仍可搜索 `data.cities` 和使用自定义城市。
- 搜索对缺失别名或英文名保持容错，不抛出异常。
- 未知交通类型由校验报错；展示层使用中性“未知交通”样式，不崩溃。
- 路线城市缺失时跳过对应轨迹；不要在动画帧中反复重试。
- 载具图片加载失败时隐藏图片但保留标签和回放状态，不阻断镜头与时间轴。

### 12.2 性能

- 全球目录只进入编辑器懒加载 chunk。
- 搜索标准化文本在目录初始化时预计算一次。
- 600 级目录使用线性过滤和排序，不引入模糊搜索依赖。
- 路线几何在旅行数据变化时构建，不随动画帧重建。
- 五张载具 SVG 只在载具层挂载后加载。
- 统计面板不新增持续动画或额外网络请求。

- `pnpm check` 与 `pnpm build` 通过。
- 桌面 Chrome smoke 通过，且无页面控制台错误。

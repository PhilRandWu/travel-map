> 体验主张：不再从地球之外“看一条路线”，而是跟随飞机或列车，从地面出发，穿过天空或沿线风景，再落回目的地。

---

## 1. 设计摘要

当前飞机与高铁动画保持地球总览视角，相机主要围绕地心移动。用户看到的是“地球在动、载具点在路线表面移动”，无法形成真实的起飞、巡航和降落体验。

本设计将载具动画升级为完整的追尾镜头：

- 飞机从程序化地面光带开始滑跑，抬头起飞，进入电影比例的巡航高度，随后下降、接地并停在目的地；
- 高铁从地面光带发车，沿线加速巡航，减速进站并停稳；
- 点击单条轨迹、自动回放、倍速与拖动进度均启用追尾镜头；
- 追尾期间锁定地球拖拽、缩放和自动旋转，通过回放控制完成暂停、跳转和结束；
- 正常完成后停留并拉回目的地城市总览；停止、切换或异常退出时恢复进入追尾前的 POV；
- 正常完成后恢复 OrbitControls 的交互能力，但保留目的地城市视角，不跳回播放前的 POV。

---

## 2. 目标与非目标

### 2.1 目标

1. 飞机具备“地面滑跑 → 起飞爬升 → 高空巡航 → 下降进近 → 接地滑跑”的完整动作。
2. 高铁具备“发车 → 加速 → 巡航 → 制动 → 进站停稳”的完整动作。
3. 相机从载具后上方跟随，载具始终处于可识别的画面位置。
4. 载具、轨迹、拖尾、摩擦光和相机的运动严格同步。
5. 相机锁定期间仍可操作暂停、倍速、进度和停止控制。
6. 动画正常结束、异常、切旅程或组件卸载后，必须恢复地球相机与交互能力。
7. 系统减少动态、静谧档和低性能环境具备明确降级。

### 2.2 非目标

- 不接入真实机场、火车站、跑道、铁路网或航空导航数据。
- 不模拟真实飞行物理、失速、天气、空中交通管制或列车动力学。
- 不增加新的第三方 3D 模型或地图服务。
- 不改变现有旅程、地点、照片、统计与轨迹数据模型。
- 不将追尾镜头扩展到照片回忆、旅程档案或普通城市浏览。
- 不提供追尾期间的自由地球拖拽。

## 3. 已确认决策

| 主题 | 决策 |
|---|---|
| 飞机视角 | B · 飞机追尾视角；镜头位于飞机后上方，飞机始终可见 |
| 高铁视角 | A · 列车追尾视角；镜头位于列车上后方 |
| 启用范围 | A · 所有载具动画；单条轨迹和旅行回放均使用追尾 |
| 拖拽行为 | A · 锁定镜头；追尾期间关闭地球拖拽、缩放和自动旋转 |
| 高度表现 | B · 统一电影比例；轨迹、载具和相机共享现有 `route.altitude` |
| 播放节奏 | C · 距离自适应；起降固定，巡航随距离变化，主体运动 7–9 秒 |
| 地面场景 | B · 抽象地面光带；不虚构具体机场或车站设施 |
| 到达收束 | A · 接地停稳后停留约 1 秒，再用约 0.9 秒拉回目的地城市总览；取消类退出恢复进入前 POV |
| 界面呈现 | B · 简化控制条；保留面包屑与回放控制，弱化其他信息 |
| 技术路线 | A · Three.js 真实追尾相机，直接控制场景相机与观察目标 |

## 4. 体验流程

### 4.1 通用规则

1. 载具在起点城市的地面光带上出现，初始高度为该载具的地面高度。
2. 追尾镜头先在约 450ms 内从当前地球视角过渡到载具后上方。
3. 主体运动结束前不使用额外转场或瞬移。
4. 正常完成后完成停稳、短暂停留与镜头拉远，停在目的地城市总览，再进入地点停留或下一次播放。
5. 停止、切换旅程、异常或卸载时，恢复进入追尾前的 POV 与交互状态。
6. 暂停时载具、相机、拖尾和环境动效一起冻结。
7. 拖动进度时直接重算目标阶段，不补播已跳过的过程。

### 4.2 飞机镜头

镜头位于飞机后上方，观察点落在飞机前方的航路切线上：

- 地面阶段能看见飞机、地面光带和前方跑道式照明；
- 起飞时飞机抬头，地平线逐渐下降，地面细节远离；
- 巡航阶段飞机保持在画面中下部的稳定位置；
- 下降时目的地重新进入前方视野，飞机轻微低头；
- 接地后飞机保持水平，减速并停在目的地光带上。

飞机姿态限制：

- 起飞抬头 8–12°；
- 下降低头 6–10°；
- 航向转弯侧倾不超过 12°；
- 姿态变化使用连续缓动，不逐帧抖动。

### 4.3 高铁镜头

镜头位于列车上后方，高度低于飞机追尾镜头：

- 发车时列车与暖金色地面双线同时点亮；
- 加速后沿线光轨由暖金过渡到冷青；
- 巡航阶段列车稳定保持在画面中下部；
- 制动时光轨前端收束，列车缓慢回到目的地光带；
- 停稳后保持水平并完成到达收束。

高铁不模拟抬头、俯冲或侧倾，只保留方向变化、加减速和贴地运动。

### 4.4 地面光带

地面光带是路线起终点的视觉隐喻，不代表真实机场或车站：

- 飞机：两道暖金色边线和中心引导灯，起飞后逐渐淡出；
- 高铁：贴地双线，沿行进方向持续点亮；
- 起点使用暖金色，目的地过渡为冷青色；
- 光带只存在于当前行程，不写入数据文件，不影响统计或地点卡片。

### 4.5 到达收束

飞机接地滑跑或列车进站停稳已经包含在主体运动的最后阶段，时长分别为 1.1 秒和 1.0 秒。主体运动结束后执行：

1. 载具停留约 1 秒，保留目的地光带与环境光；
2. 相机在约 0.9 秒内拉回目的地城市总览；
3. 释放相机锁定并恢复 OrbitControls 的交互能力，但保留目的地城市视角；
4. 自动回放继续进入地点停留节点，单条轨迹播放结束。

主体运动为 7–9 秒，到达收束额外约 1.9 秒。450ms 入场过渡与主体运动的首段重叠，不计入主体运动，也不额外增加节点时长；一次完整飞行或列车节点的时长约为 8.9–10.9 秒。

## 5. 运动模型

### 5.1 统一时间轴

每段载具运动分为五个阶段。阶段边界定义路线进度、海拔、姿态和相机距离，时间轴按阶段时长推进。

#### 飞机

| 阶段 | 路线进度 | 时长 | 高度 | 俯仰 |
|---|---:|---:|---|---|
| 地面滑跑 | 0–0.08 | 900ms | 0 | 0° |
| 起飞爬升 | 0.08–0.24 | 1400ms | 平滑升至 `route.altitude` | 0° → 10° → 0° |
| 高空巡航 | 0.24–0.78 | 2300–4300ms | `route.altitude` | 0° |
| 下降进近 | 0.78–0.93 | 1300ms | 平滑降至 0 | 0° → -8° → 0° |
| 接地滑跑 | 0.93–1 | 1100ms | 0 | 0° |

巡航时长：

```text
2300 + clamp((distanceKm - 300) / 9700, 0, 1) * 2000
```

总主体运动时长固定为 7000–9000ms，不包含 450ms 入场过渡和约 1900ms 到达收束。

#### 高铁

| 阶段 | 路线进度 | 时长 | 高度 |
|---|---:|---:|---|
| 发车 | 0–0.08 | 900ms | 地面高度 |
| 加速 | 0.08–0.24 | 1400ms | 地面高度 |
| 巡航 | 0.24–0.80 | 2500–4500ms | 地面高度 |
| 制动 | 0.80–0.94 | 1200ms | 地面高度 |
| 进站停稳 | 0.94–1 | 1000ms | 地面高度 |

巡航时长：

```text
2500 + clamp((distanceKm - 100) / 3900, 0, 1) * 2000
```

总主体运动时长固定为 7000–9000ms，不包含 450ms 入场过渡和约 1900ms 到达收束。

### 5.2 路线进度缓动

- 地面滑跑、发车：`easeInQuad`，让起步有重量；
- 起飞、加速、下降、制动：`easeInOutCubic`；
- 巡航：线性；
- 接地、进站：`easeOutCubic`。

阶段末端必须精确落在既定路线进度，不允许累计误差改变终点。

### 5.3 高度与姿态

- 飞机巡航高度直接使用现有 `route.altitude`，不创建第二套“镜头高度”。
- 飞机在 0 和 1 进度时高度必须为 0，保证首尾都落在城市地面。
- 飞机俯仰根据阶段曲线计算；巡航中的侧倾根据未来航向差计算，并限制在 ±12°。
- 高铁高度保持 `TRAIN_ALTITUDE`，俯仰与侧倾恒为 0。
- 页面进入后台时冻结时间轴；恢复可见后从暂停位置继续。

## 6. 追尾相机

### 6.1 坐标与朝向

相机基于 Three.js 世界坐标工作，不直接插值经纬度：

1. 使用 `globe.getCoords(lat, lng, altitude)` 取得载具世界坐标；
2. 使用载具前后采样点计算三维切线与局部上方向；
3. 相机位置 = 载具位置 - 切线 × 后距 + 局部上方向 × 高度；
4. 观察目标 = 载具前方采样点 + 少量上移；
5. 相机上方向使用当地地面法向，不叠加额外侧倾。

跨 180° 经线时全部使用三维向量，不进行经度数值插值。

### 6.2 镜头距离

以 `globe.getGlobeRadius()` 为 `R`：

| 状态 | 后方距离 | 上方距离 | 前方观察距离 |
|---|---:|---:|---:|
| 飞机地面 | 0.045R | 0.018R | 0.080R |
| 飞机巡航 | 0.070R | 0.030R | 0.140R |
| 高铁 | 0.032R | 0.012R | 0.060R |

飞机镜头距离随高度因子在“地面”和“巡航”参数之间平滑插值。相机与地球表面的距离不得低于 `0.012R`。

### 6.3 平滑与跳转

- 正常逐帧播放使用指数平滑，目标权重约为 `1 - exp(-8 × dt)`；
- 开始追尾时使用 450ms 入场过渡；
- 回放拖动定位时相机直接跳到目标姿态，不做跨大陆飞行动画；
- 到达收束使用 900ms 缓动；
- 切到另一段载具时先取消上一段过渡，再以 180ms 淡出旧镜头状态。

### 6.4 相机保存与恢复

进入追尾时保存：

- 相机位置、四元数与上方向；
- OrbitControls 的 `target`、`enabled`、`autoRotate`；
- 当前地球 POV。

正常完成时：

1. 相机先拉回目的地城市总览；
2. 恢复 OrbitControls 的 `enabled` 与 `autoRotate`，保留目的地城市观察目标，不恢复保存的相机 POV；
3. 进入地点停留或下一次播放。

取消类退出时：

1. 用户停止、切换旅程或回放定位到非载具节点时，恢复保存的 POV 与 OrbitControls 状态；
2. 组件卸载或异常时使用清理函数同步恢复，不播放动画。

任何恢复路径都不得留下禁用状态的 OrbitControls。

## 7. 单一时钟与模块边界

### 7.1 单一时钟

新增一个载具运动运行时，统一处理：

- 单条轨迹的一次性播放；
- 旅行回放中的当前行程；
- 播放、暂停、倍速和拖动定位；
- 载具位置、路线进度、海拔、俯仰、侧倾与阶段；
- 订阅同一帧给载具渲染和相机。

React 只接收低频阶段变化，不因 60fps 位置更新重新渲染整页。

### 7.2 纯函数模块

**`src/lib/vehicleMotion.ts`**

- 载具阶段、时长、路线进度、海拔和姿态；
- 距离自适应时长；
- 到达收束时间；
- 输入为路线、距离和已播放时间，输出可测试的运动帧。

**`src/lib/chaseCamera.ts`**

- 纯三维相机姿态计算；
- 后距、上距、观察点与局部上方向；
- 最低相机高度约束；
- 跨 180° 经线连续。

### 7.3 React 与 Three.js 适配

**`src/components/globe/hooks/useVehicleRuntime.ts`**

- 拥有唯一 `requestAnimationFrame` 时钟；
- 把一次性播放与 `ReplayRuntime` 统一成运动帧；
- 向载具层和相机层发送命令式订阅；
- 页面不可见时停在当前帧。

**`src/components/globe/hooks/useVehicleChaseCamera.ts`**

- 保存、锁定与恢复相机和 OrbitControls；
- 消费运动帧并更新 Three.js 相机；
- 处理入场、跳转、到达收束和安全退出。

**`src/components/globe/VehicleCameraStatus.tsx`**

- 显示“载具视角”和当前阶段；
- 阶段变化时进行一次可访问性播报。

### 7.4 现有模块调整

- `VehicleOverlay` 移除自己的主时间轴，只订阅运动帧更新图标、轨迹、拖尾、摩擦光和到达波纹。
- `TravelGlobe` 创建运动运行时，连接载具层、相机层和阶段提示。
- `useAutoRotate` 与 `useCameraFocus` 在相机锁定期间停止写入 POV。
- 回放节点时长 `replayNodeDurationMs` 必须包含主体运动 7000–9000ms 与约 1900ms 到达收束；不再保留独立的 3400/4300ms 常量，也不把 450ms 入场过渡计入节点时长。
- 样式增加载具视角状态、阶段提示、背景暗角与信息弱化规则。

每个代码文件原则上不超过 300 行；超过时按运行时、相机、姿态和 UI 继续拆分。

## 8. 界面与交互

### 8.1 追尾期间

- 顶部面包屑保持可见；
- 底部旅行回放控制保持完整可用；
- 当前载具阶段显示在回放控制附近，不遮挡载具；
- 旅程护照、统计、其他城市标签和其他旅程轨迹降低透明度或隐藏；
- 当前路线、载具、拖尾、摩擦光和地面光带保持清晰；
- 城市标记在追尾期间不可点击或聚焦；
- 增加低强度边缘暗角与顶部安全区，避免界面元素压住地平线。

### 8.2 状态样式

- 阶段文字：滑跑 / 起飞 / 巡航 / 下降 / 接地 / 抵达；
- 高铁阶段文字：发车 / 加速 / 巡航 / 制动 / 进站 / 抵达；
- 文字不能只靠颜色区分；
- `aria-live="polite"` 仅在阶段发生变化时更新一次；
- 追尾期间提供“镜头已锁定”的视觉说明，但不新增退出按钮。

### 8.3 相机与交互冲突

- OrbitControls 禁用拖拽、缩放和自动旋转；
- 城市点击、轨迹 hover 与反查在追尾期间暂停；
- 暂停、继续、倍速、进度和停止继续工作；
- 进度定位到地点节点时退出追尾，恢复目的地城市视角；
- 定位回行程节点时重新进入对应阶段的追尾。

## 9. 无障碍与降级

### 9.1 减少动态与静谧档

- 系统 `prefers-reduced-motion` 或静谧档启用时不进入追尾相机；
- 载具只做短淡化，路线显示最终轨迹，回放保持在目的地视角；
- 追尾播放过程中切换到静谧或系统开启减少动态时，立即停止相机跟随；
- 相机以无动画方式切到当前行程目的地，回放可继续或由用户停止。

### 9.2 低帧率

- 低帧率降档先关闭拖尾、摩擦光、暗角和次要粒子；
- 核心追尾相机与载具位置保留；
- 若继续降至静谧档，按 9.1 退出追尾；
- 不通过减少相机更新频率制造卡顿或位置跳变。

### 9.3 错误回退

- 无法取得相机、OrbitControls 或地球半径时不启用追尾；
- 路线少于两个点时保持地球视角；
- 前后采样重合时不计算方向，沿用上一帧姿态；
- 相机姿态出现 NaN 时停止更新并恢复保存状态；
- 任何异常都不得阻断回放时间轴或页面其他功能。

---

## 10. 性能要求

- 载具层与相机层共享同一帧，不创建第二个 60fps 时钟；
- 每帧只更新必要的 Three.js 相机字段和 DOM transform；
- 不因逐帧位置更新触发 React 树重渲染；
- 阶段变化最多 6 次，可作为低频 React 状态；
- 目标桌面帧率 60fps，390px 目标至少 45fps；
- 动画结束后释放临时几何、材质、事件订阅和相机锁；
- 页面进入后台时冻结运行时，不累计离线时间。

## 11. 测试与验收

### 11.1 纯函数测试

1. 飞机在 0 和 1 进度时高度为 0，巡航阶段达到 `route.altitude`。
2. 飞机起飞阶段高度单调增加，下降阶段单调减少。
3. 高铁全程保持 `TRAIN_ALTITUDE`，俯仰和侧倾为 0。
4. 短途和长途巡航时长分别落在 2300–4300ms 与 2500–4500ms 边界内。
5. 总主体运动时长始终位于 7000–9000ms。
6. 回放节点时长等于主体运动加约 1900ms 到达收束，不包含入场过渡。
7. 阶段边界连续，不出现位置、海拔或姿态跳变。
8. 相机始终位于地球表面之外，观察点在载具前方。
9. 跨 180° 经线时相机位置连续且无 NaN。

### 11.2 集成测试

1. 单条飞机轨迹播放时启用追尾相机并锁定 OrbitControls。
2. 旅行回放中的飞机与高铁分别使用正确追尾参数。
3. 暂停后载具和相机帧不再变化。
4. 拖动进度到不同阶段时相机立即切换，不补播中间过程。
5. 回放定位到 visit 节点时恢复城市视角。
6. 正常播放结束后停在目的地城市总览并恢复 OrbitControls。
7. 停止、切换旅程、异常和卸载后恢复进入追尾前的 POV。
8. 减少动态、静谧档和页面后台时不进入追尾或冻结正确状态。
9. 快速切换两段行程不会残留上一段相机、阶段提示或拖尾。

### 11.3 浏览器验收

1. 飞机从地面光带滑跑，完整起飞、巡航、下降、接地并停在成都。
2. 高铁从光带发车，完整加速、巡航、制动并停稳。

5. 到达后停留并拉回城市，随后自动回放进入地点节点。
6. 正常播放完成后停在目的地城市总览，控制条仍可用。
7. 390px 无横向溢出，阶段提示不遮挡载具或回放控制。
